# 互換仕様の機能カタログ

このディレクトリには、互換仕様で使える判定材料と実現機能をリスト化する。

ここに置く項目は、互換仕様が論理操作を作るときに利用できる機能である。複合的な API 変化がある場合も、1つの論理操作仕様の中で必要な機能を組み合わせる。

## 呼び出し元モジュールによる意味判定

呼び出し元のモジュールやパッケージから、その呼び出しが旧版の意味を期待しているか新版の意味を期待しているかを判断する。

互換仕様では、どの呼び出し元をどの版の意味として扱うかを指定する。コンパイル時には、その条件を論理操作の呼び出し意味解決へ織り込む。

## オブジェクトの現在状態による意味判定

レシーバや引数オブジェクトの現在状態から、呼び出し意味を判断する。

例えば、あるフィールドが存在していれば新版の状態、存在しなければ旧版の状態と判断できる場合に使う。

## 実行済み操作の履歴による意味判定

それまでに実行された論理操作や版固有の処理履歴から、現在の呼び出し意味を判断する。

例えば、`y()` が実行済みなら後続の `x()` を `x@v2` とみなし、未実行なら `x@v1` とみなす、といった条件を指定する。

## 特定フィールドの有無による意味判定

オブジェクトに特定フィールドが存在するかどうかを判定材料にする。

この機能は、状態表現の変更や段階的な初期化を伴う論理操作で使う。フィールドの有無だけでは意味が一意に決まらない場合は、危険箇所として記録する。

## 初期化済みフラグによる意味判定

互換仕様が定めたフラグを使い、必要な前処理や状態調整が完了しているかを判断する。

初期化済みフラグは、呼び出し意味の判定だけでなく、実行列選択や状態調整の前提条件にも使える。

## 引数の形・フォーマットによる意味判定

引数の数、型、属性、フォーマットから、どの版の呼び出し意味を期待しているかを判断する。

Python のような動的型付け言語では、引数の形が実行時まで決まらないため、この機能は静的変換では扱いにくい呼び出しを論理操作として実現するために使う。

## 観測的等価な実行列の選択

互換仕様に複数の実行列がある場合、現在状態で実行できるものを選ぶ。

実装は片方の版へ寄せてもよいし、呼び出し列へ展開してもよいし、共通実装を生成してもよい。選択結果が論理操作としての観測的等価性を壊さないことが条件である。

## 実行前の状態調整

選択した実行列の前提を満たすように、実行前に状態を調整する。

状態調整には、別版の状態表現を生成する、必要なフィールドを初期化する、履歴やフラグを更新する、状態のバージョンを揃える、といった処理が含まれる。

状態調整が不完全な場合でも実行は継続できる。ただし、その箇所は危険箇所として報告できるように記録する。
